2. PROJECT OVERVIEW
--------------------------------------------------------------------------------

TVTrack is a web-based TV show tracking platform inspired by Letterboxd. Users
can search for TV shows using the TMDB API, log watched episodes/seasons/series,
rate and review shows, add them to a watchlist, create custom lists, and interact
socially by following other users and viewing their profiles.

--- TECHNOLOGY: Proposed vs Actual ---

  Proposed                    | Actual / Changes
  ----------------------------|--------------------------------------------------
  Visual Studio 2022          | Visual Studio 2022                   [NO CHANGE]
  ASP.NET Core MVC (.NET 8)   | ASP.NET Core MVC (.NET 10)           [UPGRADED]
  SQL Server 2022             | SQL Server / LocalDB (mssqllocaldb)  [NO CHANGE]
  Entity Framework Core       | EF Core (via IdentityDbContext)      [NO CHANGE]
  TMDB REST API               | TMDB REST API                        [NO CHANGE]
  (not in proposal)           | ASP.NET Core Identity (AppUser)      [ADDED]
  (not in proposal)           | Web API controller (ShowApiController)[ADDED]
  (not in proposal)           | NUnit testing framework              [ADDED - req]

The application follows a layered architecture separating presentation logic
(Controllers + Views + ViewModels), service logic (TmdbService, Repositories),
and data access (EF Core / AppDbContext / SQL Server).

--- DATABASE: Proposed vs Actual ---

  Proposed tables (from class diagram):
    User, TVShow, Review, Rating, WatchList, CustomList (with ShareToken),
    Follow

  Actual tables in DB (from AppDbContext + Migrations):
    AspNetUsers (AppUser via Identity - extends IdentityUser with Bio,
                 ProfilePictureUrl)
    Shows (TVShow - TmdbId, Title, Overview, PosterPath, FirstAirDate,
           NumberOfSeasons)
    ShowLogs (NEW - replaces separate Rating+Review into one log entry with
              LogType: Series/Season/Episode, optional Rating, optional Review,
              SeasonNumber, EpisodeNumber, EpisodeTitle, WatchedOn)
    Follows (FollowerId, FollowedId, FollowedAt)
    WatchList (UserId, ShowId, AddedAt)
    CustomLists (OwnerId, Name, Description, CreatedAt, ShareToken)
    CustomListItems (junction table - ListId, ShowId)
    Reviews (exists as model/table but largely replaced by ShowLog)
    Ratings (exists as model/table but largely replaced by ShowLog)
    + All standard ASP.NET Identity tables

  Key change from proposal:
    The most notable design change is the introduction of the ShowLog model.
    Rather than having separate Rating and Review flows, a ShowLog entry
    captures: what type of viewing (series, season, or episode), an optional
    star rating (1-5), and optional review text all in one action. This is
    more aligned with how Letterboxd actually works and simplifies the UX.
